## 2. 项目概述

### 2.1 项目背景

当下主流UI组件库偏向通用业务、传统后台风格，缺乏AI时代专属的科技感、未来感交互样式，且体积臃肿、配置繁琐，不适合个人轻量化项目快速开发。同时市面上没有贴合个人开发者专属标识、极简高定的AI风组件体系。

基于此，Yangzai 自研个人专属组件库 Yzen-UI，聚焦AI交互、科技视觉、轻量化、高自定义，服务个人所有前端项目，打造专属开发基座与个人技术作品。

### 2.2 产品定位（V2.0 升级）

Yzen-UI 不只是一个组件 npm 包，而是「**一库双端**」的个人组件资产体系：

```
组件库 yzen-ui —— 手工精心制作的 AI 科技风 Vue 组件（核心资产）
        │
        ├── Showcase 展示站 —— 对标 beautifului.dev 的组件展示体验
        │     （长滚动锚点布局 / 编号组件列表 / 实时交互预览 / 变体切换 / 复制代码）
        │
        └── Console 管理端 —— 完整的本地组件管理应用
              （组件收录 / 元信息管理 / 分类标签 / 预览检查 / 展示配置）

Registry 数据层 —— Console 写入、Showcase 读取的组件注册表（单一真源，git 版本化）
```

- **核心定位**：轻量、极简、未来科技风、AI原生交互的个人专属组件库与组件工作台
- **差异化优势**：区别于 Element、Arco、AntD 通用商务风，主打AI数据流、光影科技、极简赛博风格；无冗余功能，极致轻量化；带有专属 Yangzai 个人标识；展示站体验对标国际一线组件展示产品
- **使用人群**：仅创作者个人使用（可后续开源）
- **核心场景**：AI对话界面、数据可视化、智能后台、科技官网、个人作品集项目

### 2.3 核心目标

1. 搭建一套统一AI科技视觉规范，实现个人所有前端项目UI风格统一；
2. 封装AI场景专属交互组件，解决通用组件库不适配AI交互的痛点；
3. 极致轻量化、高复用、低学习成本，提升个人开发效率；
4. 建成「制作—管理—展示」一体化的个人组件资产工作台，展示站达到 beautifului.dev 级别的展示质感；
5. 打造高质量个人技术开源作品，沉淀前端工程化、组件设计能力。

## 3. 产品核心特性（核心卖点）

- **AI原生风格**：内置数据流动效、光影渐变、悬浮粒子、智能加载、AI打字机等专属视觉交互；摒弃传统圆角、阴影、死板商务样式
- **轻量化极简**：按需引入、零冗余代码、体积小巧，无第三方重型依赖
- **高可配置化**：主题色、光影、动效、圆角、间距均可自定义，适配不同科技风项目
- **TS全类型覆盖**：完整类型定义，代码提示完善，适配TS项目
- **个人专属标识**：内置Yangeon专属视觉彩蛋、默认主题、水印标识，唯一性强
- **适配AI场景**：针对性封装AI对话、流式输出、内容加载、数据解析等专属组件
- **一库双端（V2.0 新增）**：Console 管理组件资产，Showcase 以 beautifului.dev 级体验对外展示；注册表数据驱动，管理端改动即时反映到展示站构建

## 4. 视觉设计规范（科技风核心标准）

整体风格：极简未来、冷调科技、光影通透、低饱和高质感、轻赛博

### 4.1 设计 Token（V2.0 新增）

所有视觉参数以 CSS Variables 作为设计 token 落地，先于组件开发：

- 色彩：主色、辅助色、背景层级（深色为默认主题）、发光色
- 形状：圆角档位、描边宽度
- 动效：时长档位、缓动曲线、动效总开关变量
- 间距与字号：见 4.2 / 4.3

### 4.2 样式规范

- 动效：匀速顺滑、轻量微动效，包含流光、呼吸、悬浮放大、淡入淡出、流式加载
- 质感：支持玻璃拟态、磨砂透明、微光描边、数据流动态

### 4.3 字体规范

- 默认字体：系统无衬线字体，保证跨端一致；数据元素（文件名、变量名、状态码）使用等宽字体
- 字号层级：12px(辅助)、14px(正文)、16px(标题)、20px(大标题)
- 字重：常规400、中等500、加粗600，拒绝粗重黑体

## 5. 产品架构与数据流（V2.0 新增）

### 5.1 Monorepo 结构

```
yzen-ui/
├── apps/
│   ├── showcase/          # 展示站：构建期渲染，静态产物可部署
│   └── console/           # 管理端：Vite 应用 + 本地 registry API（仅 127.0.0.1）
├── packages/
│   ├── yzen-ui/           # 组件库本体（发布 npm）
│   └── shared/            # registry 契约：类型定义、校验、预览容器
├── registry/
│   └── registry.json      # 组件注册表（git 版本化）
└── docs/
```

### 5.2 Registry 数据契约

```ts
interface RegistryEntry {
  key: string            // 组件标识，如 'button'
  name: string           // 展示名，如 'Button 按钮'
  description: string    // 一句话说明（展示站用）
  category: string       // basic | ai | advanced
  tags: string[]
  order: number          // 展示站编号顺序
  visible: boolean       // 是否上展示站
  source: string         // 源码位置（相对 packages/yzen-ui/src 的路径约定）
  variants: { label: string; props: Record<string, unknown> }[]
}
```

### 5.3 数据流

```
Console 编辑 ──本地API──▶ registry/registry.json ──构建期读取+校验──▶ Showcase 渲染
```

- 单一真源：元信息以 registry.json 为准；组件源码在 packages/yzen-ui，按目录约定组织
- 构建期校验：registry 引用的组件必须能被解析（目录约定 + import.meta.glob），否则 Showcase 构建失败——防止注册表与源码漂移

## 6. Showcase 展示站需求（V2.0 新增）

对标 beautifului.dev 的展示体验，作为组件库的对外展示窗口。

### 6.1 布局与导航

- 单页长滚动 + 锚点导航：组件以编号列表呈现（01、02、……），点击导航平滑滚动至对应区块，当前区块在导航中高亮
- 每个组件区块结构：**编号 + 组件名 + 一句话说明 + 实时交互预览 + 变体切换 + 复制代码**
- 顶部/侧边导航按分类分组（基础 / AI场景 / 进阶）
- 页尾：项目信息、开源许可、（预留）更新订阅入口

### 6.2 实时交互预览

- 所有组件为真实渲染的交互实例（非截图、非动图），用户可直接操作
- 预览区视觉与真实使用场景一致，深色科技风背景

### 6.3 变体切换 Playground

- 数据驱动：变体来自组件的 variants 声明（registry），展示站自动渲染切换开关（如 Solid / Glow / AI Loading）
- 切换即时重新渲染组件，无页面刷新

### 6.4 统一业务场景示例数据（V2.0 新增）

- 所有组件 demo 使用同一套虚构业务场景数据，营造真实产品感（对标 beautifului.dev 的虚构冰淇淋店）
- 建议场景：虚构的「深空观测站 / 极光实验室」AI 运营场景（观测任务、数据流、Agent 状态、告警等），与组件库 AI 定位呼应
- 示例数据统一维护在 shared 包，组件 demo 与展示站共用

### 6.5 复制代码

- 每个组件区块提供一键复制使用代码（构建期将 demo 源码以字符串注入）
- （后置）「查看源码」面板：源码展示 + 轻量语法高亮

### 6.6 展示内容管理

- 展示站的组件清单、顺序、文案、变体完全由 registry 驱动，无手工页面维护

## 7. Console 管理端需求（V2.0 新增）

完整的本地组件管理应用，「管理组件的地方」。

### 7.1 组件列表与检索

- 组件清单视图：编号、名称、分类、标签、可见状态、排序
- 按分类筛选、按名称/标签搜索

### 7.2 元信息管理

- 表单化编辑 registry 字段：名称、一句话说明、分类、标签、排序、展示开关
- 编辑保存即写入 registry.json（经本地 API），Showcase 下次构建生效

### 7.3 变体配置管理

- 可视化增删改变体：变体名 + props 预设（JSON 编辑 + 常用字段表单两种方式）
- 变体顺序调整

### 7.4 预览检查

- Console 内直接渲染组件库源组件（workspace 依赖，构建期渲染），所见即所得
- 预览容器与 Showcase 复用同一组件，保证两端展示一致

### 7.5 收录流程

- 新组件按目录约定放入组件库后，在 Console 完成元信息配置并收录上站
- （V1.2 后置增强）粘贴 Vue 单文件组件代码 / 拖入本地源码文件，在沙箱预览确认后收录

### 7.6 运行与安全

- 本地运行（Vite dev server + 本地文件 API），API 仅监听 127.0.0.1
- 预留部署：架构不锁死本地，生产化可替换为独立轻量服务并增加鉴权

## 8. 核心组件规划（分批次迭代）

### 8.1 基础通用组件（V1.0 必做）

满足基础页面搭建，全部适配AI科技风样式

- Button 按钮：发光按钮、渐变按钮、悬浮流光、AI加载按钮
- Input 输入框：磨砂输入、聚焦发光边框、智能清空
- Card 卡片：玻璃拟态卡片、悬浮抬升、光影渐变卡片
- Icon 图标：专属线性科技图标、AI主题图标集
- Layout 布局：适配科技风的栅格、容器、间距布局
- Typography 排版：统一科技风文本、标题样式

### 8.2 AI场景专属组件（核心差异化，V1.1 迭代）

- AI Chat 对话气泡：流式输出适配、打字机动效、角色区分样式
- AI Loading 智能加载：数据流旋转、粒子加载、流光加载
- Code Block 代码块：科技风高亮、复制、折叠功能
- Data Stream 数据流组件：动态数据滚动、实时刷新动效
- Prompt 提示框：AI智能提示、悬浮气泡提示
- Glass Modal 磨砂弹窗：未来感透明弹窗、无生硬遮罩

### 8.3 进阶特色组件（V1.2 迭代）

- Progress 科技进度条：流光进度、渐变进度
- Tag 标签：霓虹渐变标签、悬浮动效标签
- Empty 空状态：AI极简空页面、无数据科技插画
- Tooltip 悬浮提示：透明磨砂悬浮框
- BackTop 回到顶部：流光悬浮按钮

## 9. 功能需求详情

### 9.1 基础能力需求

1. 按需引入：支持组件单独引入，减少打包体积
2. 主题定制：支持全局修改主色、辅助色、圆角、动效开关（CSS Variables 设计 token）
3. 响应式适配：适配桌面端、移动端，保证科技风视觉不失效
4. 无障碍基础适配：基础焦点、键盘访问适配
5. 完整TS类型：所有组件props、事件、插槽全类型定义

### 9.2 特色AI能力需求

1. 流式输出适配：AI文本逐字输出、无卡顿动态渲染
2. 智能动效开关：支持全局关闭/开启所有流光、呼吸动效，适配不同项目
3. 专属水印：可选Yangeon / Yangzai 专属项目水印，强化个人标识

### 9.3 双端协同需求（V2.0 新增）

1. Registry 单一真源：组件元信息只在 registry.json 维护，双端共同遵守 shared 包的类型契约
2. 构建期一致性校验：Showcase 构建时校验 registry 与组件源码一致，漂移即失败
3. 收录即所见：Console 中的预览与 Showcase 展示使用同一渲染路径

## 10. 非功能需求

### 10.1 性能需求

- 组件打包体积极小，无冗余代码；支持 Tree-Shaking 按需打包
- 组件渲染速度快，动效不卡顿、不阻塞主线程
- Showcase 首屏性能：组件区块按需懒加载，进入视口附近再渲染；构建产物按组件分包

### 10.2 兼容性需求

- 适配现代浏览器（Chrome、Edge、Safari最新版），放弃老旧浏览器兼容，保证科技动效、玻璃拟态效果正常展示
- Console 本地文件 API 仅在本地开发环境运行

### 10.3 可维护性需求

- 代码结构统一、注释规范，方便个人长期迭代维护
- 配套完整README、组件使用文档、示例demo
- 版本迭代规范，语义化版本号管理
- registry.json 随代码进 git，元数据变更可追溯

### 10.4 安全需求（V2.0 新增）

- Console 本地 API 仅监听 127.0.0.1，不对局域网暴露
- （后置增强）动态预览外部源码时必须运行于沙箱 iframe（sandbox="allow-scripts"，无同源权限），与主应用 postMessage 通信

### V1.0 基础版本（首发版本）

### V1.2 完善迭代版本

补齐进阶特色组件、优化动效性能、新增个人专属水印；**Console 完善**（变体编辑、展示开关、排序、收录流程闭环），展示站视觉打磨（对标 beautifului.dev 质感）。
